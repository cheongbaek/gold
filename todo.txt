 1. [ ] E-STOP 안전장치 실차 확인                            ★이번 변경의 핵심★
───────────────────────────────────────────────────────────────────────────────
   책상 시험(노드 콜백 직접 호출)은 8개 항목 전부 통과했다. 아래는 사람이 실제로
   D12 를 끊어 보는 것이다. 화면은 prompt(CLI) 하나다(prompt_g 는 삭제했다).

   1-1 [ ] 자율주행(DRIVE_RUN) 중 D12 를 끊는다
           기대 · 차는 하드웨어로 즉시 정지(A·B 보드 자체 판정, ROS 무관)
                · 화면이 메뉴로 복귀, /drive_state : DRIVE_RUN → IDLE
                · /drive_event : "🚨 E-STOP — 자율주행 취소, 메뉴로 복귀"
           확인 · ros2 topic echo /drive_state   (다른 터미널에서)
   1-2 [ ] E-STOP 물린 채로 2) 주행 시작을 눌러 본다
           기대 · 거절. "🚨 주행 시작 실패 — E-STOP 체결 중이다(해제 후 다시)"
                · GUI 는 주행 버튼 자체가 비활성이어야 한다
   1-3 [ ] E-STOP 물린 채로 1) 매핑 시작
           기대 · 정상 시작(MAP_HEADING). 차가 안 구르므로 점은 안 쌓인다 —
                  ★그게 정상이다★(경로가 오염되지 않는다는 뜻)
   1-4 [ ] 매핑 중에 D12 를 끊는다
           기대 · 매핑이 ★취소되지 않는다★ (MAP_* 유지). 해제하면 그대로 이어간다
   1-5 [ ] 해제 후 2) 주행 시작
           기대 · 정상 진입(DRIVE_HEADING). "✅ E-STOP 해제 — 자율주행 가능"
   1-6 [ ] 주행 대기 중(스위치 전환 대기)에 D12 를 끊는다
           기대 · 대기가 자동 취소되고 메뉴로 돌아온다

 2. [ ] 수동 계측 런치 — 조이스틱 / 레버 창 + 기록          [전용 런치 2개 신설]
───────────────────────────────────────────────────────────────────────────────
   ★driving 과 joystick·master 를 동시에 띄우지 말 것★
     셋 다 /cmd_vel_raw 를 20Hz 로 발행한다. driving 은 IDLE 에서도 계속 0 을
     내므로(정지 유지가 목적), 같이 띄우면 조종 명령이 매 틱 0 으로 덮인다.
     그래서 driving 을 빼고 조종 노드를 넣은 런치를 따로 만들었다. 하나만 쓴다:

     ros2 launch white1 joy.launch.py       ← 조이스틱으로 몬다(차에 타서)
     ros2 launch white1 master.launch.py    ← 마우스 레버 창으로 몬다
                                              (값을 정확히 지정·재현하기에 유리)

   둘 다 arduino · iahrs · speed · GPS · record 를 함께 띄운다. record 는
   force_record 로 도므로 ★런치하는 즉시★ 파일이 열린다(조종 노드를 잡기 전
   대기 구간도 함께 들어간다 — 나중에 잘라 보면 된다).

   기대 · ros2bag/manual-<날짜>_<시각>.csv 가 열리고 20Hz 로 쌓인다.
          Ctrl-C 로 닫는다. (책상 확인 완료 : 3.7초에 74행)
   조작 · ★D5 를 자율주행으로★ 올려야 조종 명령이 나간다(수동조종 위치에서는
          A보드가 페달만 본다). 조이스틱은 영점 뒤 SWA, master 는 발행 ON 토글.
   주의 · driving 을 안 띄웠으므로 /drive_diag 계열 열(cte_m, ref/out/meas,
          cte_i_term_deg, goal_phase …)은 통째로 빈다 — ★정상이다★.
          채워지는 것 : fix_*, imu_*, encoder_sum, speed_kmh, cmd_*, brake,
                        steer_measured, throttle_raw, vehicle_mode, estop, board_status
   주의 · 조이스틱은 E-STOP 중에는 게이트에 막힌다("E-STOP" 사유 표시). 정상이다.

 3. [ ] 리니어 1단·코스트 감속도 실측          ★다음 기능(코너 1단 제동)의 전제★
───────────────────────────────────────────────────────────────────────────────
   2번 구성 그대로, 넓고 곧은 곳에서. 앞뒤 사람·장애물 없는 것을 먼저 확인.

   3-1 [ ] a1 (리니어 1단) : 4펄스 정속 → L스틱 아래 1/3~2/3 구간(=1단) 0.5초 →
                             중립. 3회 반복.                  a1 = ____ m/s²
   3-2 [ ] a0 (코스트)     : 4펄스 정속 → 스틱 중립(펄스 0), 브레이크 없이
                             굴러가게 둔다. 3회.               a0 = ____ m/s²
   3-3 [ ] a2 (2단, 확인용): 종전 실측 2.2 m/s² 가 맞는지.     a2 = ____ m/s²

   산출 방법 · CSV 의 fix_lat/fix_lon 으로 GPS 변위속도를 만들어 기울기를 뽑는다.
              ★speed_kmh 열을 쓰지 말 것★ — 지속 감속을 자세로 오인해 스스로
              지운다(speed.py 헤더, 2026-08-12 실차 로그로 확인된 한계).
   판정     · a1 ≥ 1.2 m/s² → 5펄스 상향 검토 가능(5항)
              a1 < 1.2 m/s² → 4펄스 유지. 1단 코너제동만 도입한다

 4. [ ] 코너 1단 선행제동 — 구현 후 검증          (3번 결과를 보고 착수. 미구현)
───────────────────────────────────────────────────────────────────────────────
   설계 요지 · corner_speed 가 이미 아는 v_corner·gate_dist 로
               a_req = (v² − v_corner²) / (2·(gate_dist − 마진)) 을 만들고,
               a_req 가 코스트 한계(a0)를 넘으면 1단을 문다. 코너에 다가갈수록
               a_req 는 단조 증가하므로 채터링이 구조적으로 안 생긴다.
   방어      · 저속 금지선(실측 2.5펄스 미만이면 안 문다 — A보드 기동 블랭킹 재유발)
               최소 유지 0.25s / 해제 후 락아웃 0.8s / 한 코너 최대 2회 / 상한 1.5s
   검증 항목
   4-1 [ ] 코너 진입 실측속도가 v_corner 에 실제로 도달하는가 (로그의 meas vs ref)
   4-2 [ ] 한 코너에서 brake 가 몇 번 물렸나 — ★2회 이하★ 여야 한다
   4-3 [ ] 제동 중 조향이 계속 나가는가 (cmd_steer_deg 가 0 으로 끊기지 않을 것)
   4-4 [ ] 제동 해제 직후 재기동에서 엔코더 허수 카운트가 튀는가 (encoder_sum)
   4-5 [ ] max|CTE| 가 종전보다 나빠지지 않았는가


───────────────────────────────────────────────────────────────────────────────
 5. [ ] 5펄스 직선 부스트 — 4번 검증 후                                (미구현)
───────────────────────────────────────────────────────────────────────────────
   요지 · 기준은 4펄스로 두고, far preview(14m) 안에 코너가 없을 때만 5펄스를 허용.
          조건이 깨지면 즉시 4로 되돌린다(올릴 때만 느리게).
   숫자 · 5펄스(4.42m/s)에서 조향은 도로휠 14.8°(R≈4.7m)에서 포화한다.
          코스트만으로 5→2펄스 감속에는 16~27m 가 필요해 preview 14m 를 넘는다.
          → ★1단 제동 없이 5펄스로 올리면 안 된다★
   5-1 [ ] 부스트가 직선에서만 걸리는가 (로그에서 ref=5 구간의 전방곡률 확인)
   5-2 [ ] 실측이 5.5펄스를 넘는 구간이 있는가 (있으면 부스트 즉시 취소가 동작해야)
   5-3 [ ] 코너 진입 전에 4펄스로 내려오는가

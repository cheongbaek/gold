# 리니어 제동력 실측 — 금색차 kasa

> 측정 로그 : `ros2bag/a1a2.csv` (2026-08-14, 186초, RTK **Fixed 100%**)
> 분석 방법 : GPS 변위 속도. **`speed_kmh` 열은 쓰지 않았다** — speed.py 는 지속 감속을
> 자세로 오인해 스스로 지운다(그 파일 헤더의 실측 근거 참고). 5Hz fix 두 점(0.2초)

> 으로 잡아 `a = Δv / Δt` 를 냈다.

## 3. 설계에 미치는 영향

- **`BRAKE_GATE_DECEL = 2.0` (driving.py 곡률 선행제동의 가정)은 2단에서만 참이다.**
  코스트만으로는 0.4 수준이라 그 가정의 **1/5** 다. 지금 코너 감속이 설계보다 늦게
  듣는 이유가 이것이다.
- **1단으로 코너 선행제동(todo.txt 4항)** : 판정선으로 두었던 `a1 ≥ 1.2 m/s²` 에
  **아직 못 미친다**(평균 0.88). 다만 모든 1단 구간에서 **지령펄스가 5~9로 살아 있었다** —
  구동을 끊고(자율주행에서는 arduino 가 브레이크>0 이면 A보드 REF 를 0 으로 덮는다)
  다시 재면 이보다 세게 나올 것이다. **재측정 전에는 1단만으로 5펄스를 받치지 못한다.**
- **5펄스 상향(todo.txt 5항)은 보류.** 4.42 m/s 에서 2펄스까지 줄이는 데 1단으로 11.1 m,
  코스트로는 23.8 m 가 필요하다 — 전방 스캔 상한(`CURVE_PREVIEW_FAR_MAX = 14 m`)을 넘는다.
  2단(4.4 m)이라면 들어오지만, 2단은 '감속'이 아니라 '정지'라 코너에서 쓸 수 없다.
- **종점 접근제동(2단 + 5 m)은 충분하다.** 4펄스에서 2.8 m 면 5 m 안에서 끝난다.

## 4. 다음에 다시 잴 때

1. **구동을 끊고 재라.** 자율주행 모드(D5 자율) + `/brake_level` 로 제동하면 arduino 가
   A보드 REF 를 0 으로 덮으므로 순수 제동이 된다. 이번 로그는 수동/레버가 섞여
   구동이 살아 있었다.
2. **1단은 초기속도 4펄스 고정으로** 3회 이상. 같은 속도에서 재야 비교가 된다.
3. `speed_kmh` 열이 아니라 **`fix_lat/fix_lon`** 으로 산출할 것(위 방법 절 참고).

# 부록 A — 신호등 정지 뒤 재출발 실패 (2026-08-14)

> 로그 : `ros2bag/route_20260814_161131-20260814_161246.csv`
> 증상 : 빨간불 정지는 잘 되는데, 해제 뒤 차가 다시 출발하지 못했다.

**ROS·아두이노 경로는 결백하다.** `/drive_pulse_cmd` 는 arduino 가 시리얼에 쓴
페이로드를 그대로 발행하는 토픽이라 '무엇이 A보드까지 갔는가'의 직접 증거다:

| t [s] | brake | `/cmd_vel_raw` | **A보드로 나간 펄스** | 엔코더 |
|---|---|---|---|---|
| 10.50 | 2 | 4 | **0** | 8 | 제동 시 구동 차단(정상) |
| 15.40 | **0** | 4 | 0 | 0 | 해제 |
| **15.80** | 0 | 4 | **4** | **0** | **4펄스가 A보드로 나갔다** |
| ~28.2 | 0 | 4 | **4 유지 12.4 s** | **0 계속** | GPS 이동 0.03 m |

같은 구간의 방증도 전부 정상 : `vehicle_mode=True`, `estop=False`,
`board_status=A:1,B:1`, `control_state=True`, `/cmd_vel_raw` 20 Hz 도착(조향값이
258/260 샘플에서 변한다), A보드 텔레메트리 살아 있음(`throttle_raw` 161~172 변동).

**남은 용의자 — 리니어가 0단으로 완전히 안 돌아갔을 가능성.**
B보드는 0단 복귀를 `BRAKE_HOME_MS = 1000 ms` **REV 고정시간**으로만 한다(위치를 보지
않는다). 2단(pot 850)에서 0단(≈310)까지 540카운트를 1초에 못 내려오면 **페달을 일부
밟은 채로 멈춘다.** 그리고 처짐 보충은 “0단은 위치 개념이 없다”며 건너뛰므로 스스로
더 내려가지도 않는다. 3펄스로 정상 출발하는 차가 4펄스를 12초 받고 안 움직였다는
사실이 이 가설과 맞는다.

**확정하려면 계측이 필요하다** — B보드 텔레메트리(`P,<조향각>,<모드>`)에 리니어 위치가
없어서 로그에 안 남는다. 다음 중 하나:
1. (30초) 자율주행 모드에서 브레이크 2단 → 0단 후 **로드가 끝까지 들어가는지 눈으로** 본다.
2. B보드 텔레메트리를 `P,<조향각>,<모드>,<브레이크단계>,<리니어pot>` 로 늘리고
   arduino 가 `/brake_state`·`/linear_pot` 으로 발행 → record 가 적는다.
3. 원인이 확정되면 펌웨어에서 0단 복귀를 **고정 1초 → 위치 기준(pot ≤ 0단+여유), 최대 N초** 로.

# 부록 B — 신호등 인지 기록 열 (2026-08-14 추가)

`record.py` 가 세 열을 더 적는다. `brake_level` 만으로는 '리니어가 물렸다'는 **결과만**
남고 그 **근거**가 남지 않아서다.

| 열 | 내용 |
|---|---|
| `tl_state` | `RED` / `RED_FAR` / `GREEN` / `UNKNOWN` — 프레임 판정 |
| `tl_near_metric` | 근접도 게이트에 걸리는 값(빨간 박스 중 최대). 기본 단위 **박스 높이[px]** |
| `tl_red_far` | 이번 프레임이 `RED_FAR` 인가 = 빨갛지만 아직 멀다고 본 것 |

읽는 법 :

```
tl_state=RED     + tl_near_metric 60  → 가까워서 섰다(정상)
tl_state=RED     + tl_near_metric 26  → 임계(25px)를 겨우 넘어 멀리서 섰다
tl_state=RED_FAR + tl_red_far=True    → 빨갛지만 멀다고 보고 안 섰다
```

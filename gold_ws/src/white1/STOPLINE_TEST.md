# 정지선 앞 정지 — 시험 절차서

> 대상 : `white1/traffic_light.py` 의 정지선 관문 (2026-08-14 추가)
> 짝 문서 : `BRAKING.md`(제동 실측) · `todo.txt` 8항(신호등 근접도 임계)
> 자동 판정 : `python3 ~/gold/sl_check.py <주행 CSV>` — 아래 판정 기준을 그대로 계산한다

**이 기능이 하는 일은 하나뿐이다** — 빨간불이 확정됐을 때, 정지선이 보이면 그것이
트리거 행에 닿을 때까지 브레이크를 **참는다**. 정지선을 못 보면 종전대로 그 자리에서
선다. 그래서 시험의 절반은 *"정지선이 실제로 보이는가"*, 나머지 절반은
*"참았다가 제때 밟는가"* 다.

**⚠️ 이 기능의 실패는 두 방향이고, 비용이 다르다**

| 실패 | 결과 | 비용 |
|---|---|---|
| 정지선을 못 본다 | 종전대로 그 자리에서 선다 | **없음** (기존 동작) |
| 없는 정지선을 본다 | 최대 5초 늦게 선다 | **크다** — 빨간불에 안 서는 것 |

그래서 아래 순서는 **오검출을 먼저 잡고**(단계 1·2) 나서 동작을 본다(단계 3 이후).

### 안전 수칙 (전 단계 공통)

- 정지선 시험은 **사람·차량이 없는 곳**에서 한다. 리니어 2단은 1초 안에 세우는 힘이다.
- 실차 접근은 **2펄스(약 1.8m/s)로 먼저** 하고, 통과한 뒤에만 4펄스로 올린다.
- **E-STOP(D12)에 사람이 손을 대고 있는다.** 이 노드는 시험 중 스스로 브레이크를 건다.
- 노드가 브레이크를 물린 채 죽으면 **D5 를 수동조종으로 내린다** — arduino 가 캐시를
  지운다. 그것이 유일한 탈출구다(`traffic_light.shutdown_release` 주석).
- 시험 중에는 `master.launch.py` 하나만 띄운다. `driving` 과 조종 노드를 같이 띄우면
  `/cmd_vel_raw` 를 셋이 다툰다(todo.txt 2항).

## 단계 1 — 정지선이 화면에 잡히는가 ★이 단계가 관문이다★

> 구 white 실측에서 `stop_line_dist` 는 **100% 미검출**이었다(camera_judgment.py 주석).
> 원인이 모델인지 파이프라인인지 기록에 없다. **여기서 안 잡히면 나머지 단계는 할
> 필요가 없다** — `sl_enable:=false` 로 두고 접으면 종전 동작 그대로다.

**실행** (차량 위, 정차 상태. 노면에 실제 정지선 또는 테이프 정지선이 있는 곳)

```bash
ros2 launch white1 master.launch.py sl_gate_red_s:=99999.0
```

`sl_gate_red_s` 를 크게 주는 이유 : 평소에는 **빨간 박스를 봤을 때만** 정지선 추론이
돈다(비용 절약). 신호등 없이 정지선만 보려면 이 관문을 열어야 한다.

**볼 것** — `Traffic Light` 창

- **자홍색 폴리곤** = 정지선 마스크, **자홍색 점** = 그 최하단(판정에 쓰는 점)
- **가로선** = 트리거 행. 정지선이 이 선 아래로 내려오면 주황색으로 바뀐다
- HUD 오른쪽 `sl 0.62/0.75` = 지금값/트리거

| # | 판정 기준 | 합격 | 결과 |
|---|---|---|---|
| 1-1 | 정지선 3m 이내에서 마스크가 잡히는가 | **끊기지 않고 계속** 잡힌다 | [ ] |
| 1-2 | 최하단 점이 정지선의 **차 쪽 가장자리**에 붙는가 | 눈으로 확인 | [ ] |
| 1-3 | 차체(앞바퀴·프레임)를 정지선으로 잡는가 | **한 번도 없어야** 한다 | [ ] |
| 1-4 | 횡단보도·차선·그림자·타이어 자국을 잡는가 | 없거나, 잡혀도 `sl` 이 트리거 미만 | [ ] |
| 1-5 | 정지선이 없는 곳에서 `sl --/0.75` 인가 | 빈 노면에서 검출 0 | [ ] |

**기록란**

```
정지선이 처음 잡히기 시작하는 거리 = ______ m   (멀수록 좋다)
정지선이 차체에 가려 사라지는 거리 = ______ m   ← ★트리거 행의 물리적 하한★
오검출된 것(있으면) : ____________  그때 sl = ______
```

**불합격이면 — 순서대로 시도**

| 증상 | 만질 값 | 비고 |
|---|---|---|
| 아예 안 잡힌다 | `sl_conf:=0.15` | 임계를 내려 먼저 격리한다 |
| 얇게/짧게만 잡혀 걸러진다 | `sl_min_width_frac:=0.08` | 기본 0.12 = 화면 폭의 12%(1920px 중 230px) |
| 그래도 안 잡힌다 | `sl_enable:=false` | **접는다.** 모델 재학습 문제지 코드로 풀 수 없다 |
| 엉뚱한 것을 잡는다 | `sl_min_width_frac` ↑ / `sl_conf` ↑ | 1-4 가 불합격이면 여기서 반드시 잡고 간다 |

## 단계 2 — 트리거 행 정하기 ★차를 세워 놓고 잰다(주행 불필요)★

지금 기본값 `sl_trigger_y_frac = 0.75` 는 **근거 없는 값**이다. 8항의 25px 과 같은 처지다.

**방법**

1. 노면에 테이프로 정지선을 만든다 — **폭 1m 이상, 두께 10cm 이상**(모델 학습 조건)
2. 차 **앞범퍼**가 정지선에서 아래 거리가 되도록 차를 대고, HUD 의 `sl` 값을 읽는다
3. 표를 채운다 (한 번 재 두면 다시 잴 일이 없다)

| 정지선까지 거리 | 1.0 m | 1.5 m | 2.0 m | **2.5 m** | **3.0 m** | 4.0 m | 5.0 m |
|---|---|---|---|---|---|---|---|
| HUD `sl` 값 | | | | | | | |

**트리거 값을 고르는 근거 — `BRAKING.md` 2절**

| 접근 속도 | 2단 정지거리(보수적 2.2 m/s²) | 반응 지연 0.6s 포함 |
|---|---|---|
| 2펄스 1.77 m/s | 0.71 m | **1.8 m** |
| 4펄스 3.54 m/s | 2.8 m | **4.9 m** |

- **2펄스로 먼저 시험한다** → 트리거는 표의 **2.0~2.5m** 칸 값
- 4펄스로 올릴 때 → **4.0~5.0m** 칸 값. 그 거리에서 정지선이 안 잡히면(단계 1 기록)
  **4펄스로는 정지선 앞 정지가 성립하지 않는다** — 접근 속도를 낮추거나 접는다

| # | 판정 기준 | 합격 | 결과 |
|---|---|---|---|
| 2-1 | `sl` 값이 거리에 대해 **단조 증가**하는가(가까울수록 큼) | 표가 뒤집히지 않는다 | [ ] |
| 2-2 | 고른 트리거가 **차체 가림 거리보다 멀리** 있는가 | 1-1 기록과 비교 | [ ] |
| 2-3 | 같은 위치에서 값이 안정적인가 | 흔들림 ±0.02 이내 | [ ] |

```
정한 값 :  sl_trigger_y_frac = ______   (근거: ____m 지점, 접근 ____펄스)
```

## 단계 3 — 판정표 4갈래 재현 ★차를 세워 놓고, 리니어는 실제로 문다★

사람이 신호등 목업과 정지선 판때기를 들고 움직여 **4가지 경로를 전부 밟아 본다.**
차는 굴리지 않는다. `master` 창의 **'신호등 인지' 체크박스를 켜야** 개입한다(D5 는
자율주행 위치여야 리니어가 물린다).

```bash
ros2 launch white1 master.launch.py sl_trigger_y_frac:=<단계 2 값>
```

| # | 만드는 상황 | 기대 동작 | 기대 로그 | 결과 |
|---|---|---|---|---|
| 3-1 | 빨간불만 보여준다 (정지선 없음) | 0.4초 뒤 **즉시 2단** | `🚦🛑 … [정지선 없음]` | [ ] |
| 3-2 | 빨간불 + 정지선을 **트리거 행 위**(멀리)에 둔다 | **안 문다.** HUD 에 `WAIT` | `🚦⏸ 빨간불 확정 — 정지선 대기 중` | [ ] |
| 3-3 | 그 상태에서 정지선을 **트리거 행 아래**로 내린다 | 즉시 2단 | `🚦🛑 … [정지선 앞]` | [ ] |
| 3-4 | 3-2 대기 중에 정지선을 **치운다**(가린다) | **0.5초 뒤** 2단 | `🛑 정지선을 놓쳤다 — 이미 선 위다` | [ ] |
| 3-5 | 3-2 대기를 **5초 이상** 유지한다 | 5초에 2단 | `🚦 정지선 대기 상한 5.0초 초과` | [ ] |
| 3-6 | 3-2 대기 중 신호등을 **카메라에 바짝** 붙인다 | 즉시 2단 | `🚦 신호등이 코앞이다` | [ ] |

**동시에 확인할 것**

- 3-2 대기 구간에서 `ros2 topic echo /brake_level` 에 **2 가 한 번도 안 나온다**
- 3-2 대기 구간에서 `ros2 topic echo /tl_brake_req` 가 **계속 0** 이다
  (이게 0 이 아니면 master·driving 이 대신 물어 버린다)
- 2단이 물릴 때 **리니어 소리**가 나고, 해제 시 되돌아온다

> **3-4 가 이 기능에서 제일 미묘한 항목이다.** '놓쳤다'는 적극적 인지가 아니라
> *"`sl_stale_s`(0.5초) 동안 못 봤다"* 를 그렇게 해석하는 것이다. 접근하면 정지선은
> 차체에 가려 **반드시** 사라지므로, 그 소실을 "이미 선 위"로 읽는 것이 안전한 방향이다.
> 대가는 **최대 0.5초의 지연**(2펄스에서 0.9m, 4펄스에서 1.75m)이고, 그 몫은 단계 2의
> 트리거 선택에 이미 들어 있어야 한다.

**자동 판정**

```bash
python3 ~/gold/sl_check.py                    # 파일 선택창
```

**판정 기준** (sl_check.py 가 그대로 계산한다)

| # | 항목 | 합격 | 불합격이면 |
|---|---|---|---|
| 4-1 | `sl_wait=True` 구간이 존재하는가 | **≥ 0.3초** | 정지선을 못 봤다 → 단계 1 로 |
| 4-2 | 대기 구간에 `brake_level=2` 가 섞였는가 | **0회** | 다른 발행자가 물었다(driving?) |
| 4-3 | 체결 시각의 `sl_y` | **트리거 ±0.03** | 놓침 경로로 물렸다 → 트리거 ↓ |
| 4-4 | 정지 사유 로그 | `[정지선 앞]` | `[없음]`=인지실패 / `[놓침]`=트리거 높음 |
| 4-5 | 실제 정지 위치(범퍼→정지선, 자로 잰다) | **0 ~ 1.5 m 앞** | 아래 조정표 |
| 4-6 | 브레이크 채터링(2↔0 왕복) | **0회** | 8항 회귀 — `red_release_hold_s` 확인 |
| 4-7 | 정지 유지 중 `tl_near_metric` | **0 이 되지 않는다** | 등기구 소실 → 카메라 틸트 |
| 4-8 | 대기 상한(5초) 발동 | **없어야** 한다 | 트리거가 도달 불가 → 트리거 ↓ |
| 4-9 | 카메라 fps | **≥ 25** | `sl_interval:=2` |

**기록란**

```
접근 펄스 ____ / 대기 시작 시 sl = ______ / 체결 시 sl = ______
대기 지속 ______ 초 / 대기 중 이동거리 ______ m
실제 정지 위치 : 정지선 ______ m 앞 (앞범퍼 기준)
```

**정지 위치 조정 — 방향을 헷갈리지 말 것**

`sl_y` 는 **가까울수록 크다.** 따라서

| 증상 | 조치 | 이유 |
|---|---|---|
| 정지선을 **지나쳐** 섰다 | `sl_trigger_y_frac` 를 **낮춘다** | 더 먼 거리(작은 y)에서 밟는다 |
| 정지선보다 **너무 멀리** 섰다 | `sl_trigger_y_frac` 를 **올린다** | 더 가까이 붙어서 밟는다 |
| 지나쳤는데 로그가 `[정지선 놓침]` | `sl_stale_s:=0.3` 도 함께 | 소실 판정이 늦어 0.5초를 더 갔다 |

한 번에 한 값만 바꾸고 4단계를 다시 돈다. 2펄스에서 4-1~4-9 를 전부 통과한 뒤에만
4펄스로 올린다(**트리거 값도 단계 2 표의 4~5m 칸으로 함께 바꾼다**).

## 단계 5 — 회귀 시험 ★기존 동작이 안 깨졌는지★

이 기능의 설계 전제는 *"정지선이 없으면 종전과 완전히 같다"* 이다. 그것을 확인한다.

| # | 시험 | 실행 | 합격 기준 | 결과 |
|---|---|---|---|---|
| 5-1 | 정지선 없는 신호등 접근 | 단계 4 와 같되 정지선 없는 곳 | `[정지선 없음]`, `sl_y` 가 −1, RED→2단 **0.4~0.6초** | [ ] |
| 5-2 | 기능 자체를 끄고 접근 | `sl_enable:=false` | 5-1 과 **같은 시간**에 선다 | [ ] |
| 5-3 | 초록불 해제 | 단계 4 정지 상태에서 초록 전환 | brake 0 까지 **1.0 ± 0.2초** | [ ] |
| 5-4 | RED_FAR 구간 | 멀리 있는 빨간불 | `tl_red_far=True` 구간의 brake **끝까지 0** | [ ] |
| 5-5 | 체크박스 해제 | 대기 중에 '신호등 인지' 를 끈다 | 즉시 손 뗌, `/tl_brake_req` 0 | [ ] |
| 5-6 | 카메라 두절 | 대기 중 usb_cam 을 죽인다 | 개입 없음(fail-open), 경고만 | [ ] |

> 5-1 의 **0.4~0.6초**가 핵심이다. 정지선 관문은 *정지선이 보일 때만* 끼어들어야 하며,

## 부록 A — 증상별 파라미터 조정표

| 증상 | 값 | 기본 | 방향 |
|---|---|---|---|
| 정지선을 못 잡는다 | `sl_conf` | 0.30 | ↓ 0.15 |
| 얇은 정지선이 걸러진다 | `sl_min_width_frac` | 0.12 | ↓ 0.08 |
| 오검출(횡단보도·차선) | `sl_min_width_frac` / `sl_conf` | 0.12 / 0.30 | ↑ |
| 정지선을 지나쳐 선다 | `sl_trigger_y_frac` | 실측값 | ↓ |
| 너무 멀리 선다 | `sl_trigger_y_frac` | 실측값 | ↑ |
| 놓침 판정이 늦다 | `sl_stale_s` | 0.5 | ↓ 0.3 |
| 대기가 자꾸 조기 종료된다 | `sl_stale_s` | 0.5 | ↑ 0.8 |
| 오검출 한두 프레임에 대기가 걸린다 | `sl_hold_s` | 0.2 | ↑ 0.4 |
| 대기가 너무 길게 유지된다 | `sl_wait_max_s` | 5.0 | ↓ 3.0 |
| 코앞에서도 안 밟는다 | `sl_override_gate_ratio` | 1.6 | ↓ 1.3 |
| fps 가 떨어진다 | `sl_interval` | 1 | ↑ 2 |
| 정지 유지 중 굴러간다 | 카메라 틸트 5~8° 또는 `tl_stop_latch:=true` | — | 8-5 참고 |

**측정된 비용** (이 PC, 1920×1080, cuda:0) : 신호등만 4.3 ms/frame → 정지선까지 7.5 ms.
30fps 예산 33.3 ms 대비 여유가 크므로 `sl_interval=1` 이 기본이다.

## 부록 B — CSV 열 읽는 법

`record.py` 가 남기는 정지선 관련 열은 둘이다.

| 열 | 뜻 |
|---|---|
| `sl_y` | 정지선 최하단 y ÷ 프레임 높이(0~1). **−1 = 미검출** |
| `sl_wait` | RED 확정인데 정지선이 멀어 **참고 있는** 구간 |

신호등 3열과 나란히 놓으면 판정 경로가 그대로 드러난다.

| `tl_state` | `sl_y` | `sl_wait` | `brake_level` | 해석 |
|---|---|---|---|---|
| RED | 0.42 | True | 0 | 빨간불 확정, 정지선 기다리는 중 — **의도한 동작** |
| RED | 0.78 | False | 2 | 정지선 앞에서 밟았다 — **정상** |
| RED | −1 | False | 2 | 정지선을 못 보고 그 자리에서 섰다 — 종전 동작 |
| RED | −1 | False→2 | 2 | 대기하다 정지선을 놓쳐 밟았다 — 트리거가 높다 |
| RED_FAR | 0.30 | False | 0 | 멀다고 보고 안 섰다 — 정상 |

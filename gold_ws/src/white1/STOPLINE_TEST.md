# 정지선 앞 정지 — 시험 절차서

> 대상 : `white1/traffic_light.py` 의 정지선 관문
> (2026-08-14 추가 → **2026-08-19 2단계 제동 + BEV 픽셀 거리로 개편**)
> 짝 문서 : `BRAKING.md`(제동 실측) · `todo.txt` 8항(신호등 근접도 임계)
> 자동 판정 : `python3 ~/gold/sl_check.py <주행 CSV>` — 아래 판정 기준을 그대로 계산한다

**이 기능이 하는 일** — 빨간불이 확정됐을 때, 정지선이 보이면 **두 단계로** 선다:
정지선까지 `sl_brake1_px` 안으로 들어오면 **1단 예비제동**으로 부드럽게 줄이고,
`sl_brake2_px` 안으로 들어오면 **2단으로 확정 정지**한다. 정지선을 못 보면 종전대로
그 자리에서 즉시 2단이다. 그래서 시험의 절반은 *"정지선이 실제로 보이는가"*,
나머지 절반은 *"두 문턱에서 제때 무는가"* 다.

**거리는 화면의 행이 아니라 BEV 픽셀이다** — 원본 화면의 행은 원근 때문에 거리에
비례하지 않아 문턱을 둘로 나눌 수 없다. 그래서 어안 왜곡을 펴고(`camera_model.py`)
BEV 로 옮긴 뒤 **정지선 최근접점 → 앞범퍼 픽셀 거리** 하나로 판정한다.
**그만큼 단계 2(캘리브)가 이 시험의 무게중심이 됐다.**

**⚠️ 이 기능의 실패는 두 방향이고, 비용이 다르다**

| 실패 | 결과 | 비용 |
|---|---|---|
| 정지선을 못 본다 | 종전대로 그 자리에서 선다 | **없음** (기존 동작) |
| 없는 정지선을 본다 | 최대 8초 늦게 선다(그동안 1단으로는 감속) | **크다** — 빨간불에 안 서는 것 |

그래서 아래 순서는 **오검출을 먼저 잡고**(단계 1·2) 나서 동작을 본다(단계 3 이후).

### 안전 수칙 (전 단계 공통)

- 정지선 시험은 **사람·차량이 없는 곳**에서 한다. 리니어 2단은 1초 안에 세우는 힘이다.
- 실차 접근은 **2펄스(약 1.8m/s)로 먼저** 하고, 통과한 뒤에만 4펄스로 올린다.
- **E-STOP(D12)에 사람이 손을 대고 있는다.** 이 노드는 시험 중 스스로 브레이크를 건다.

  지운다. 그것이 유일한 탈출구다(`traffic_light.shutdown_release` 주석).
- 시험 중에는 `master.launch.py` 하나만 띄운다. `driving` 과 조종 노드를 같이 띄우면
  `/cmd_vel_raw` 를 셋이 다툰다(todo.txt 2항).

## 단계 1 — 정지선이 화면에 잡히는가 ★이 단계가 관문이다★

> 구 white 실측에서 `stop_line_dist` 는 **100% 미검출**이었다(camera_judgment.py 주석).
> 원인이 모델인지 파이프라인인지 기록에 없다. **여기서 안 잡히면 나머지 단계는 할
> 필요가 없다** — `sl_enable:=false` 로 두고 접으면 종전 동작 그대로다.

**실행** (차량 위, 정차 상태. 노면에 실제 정지선 또는 테이프 정지선이 있는 곳)

```bash
ros2 launch white1 master.launch.py sl_gate_red_s:=99999.0
```

`sl_gate_red_s` 를 크게 주는 이유 : 평소에는 **빨간 박스를 봤을 때만** 정지선 추론이
돈다(비용 절약). 신호등 없이 정지선만 보려면 이 관문을 열어야 한다.

**볼 것** — `Traffic Light` 창

- **자홍색 폴리곤** = 정지선 마스크, **자홍색 점** = 그 최하단
- **노란 사다리꼴** = BEV 로 펴는 영역(`bev_src_pts`). 단계 2 에서 이것을 맞춘다
- **우하단 BEV 썸네일** — 위에서 내려다본 그림. 그 안의 가로선 셋이 판정의 전부다
  - **초록 `BUMPER`** = 거리 0(앞범퍼)  · **빨강 `B2`** = 2단 문턱 · **주황 `B1`** = 1단 문턱
- HUD `sl 214px B1:240 B2:60` = 지금 거리 / 두 문턱

| # | 판정 기준 | 합격 | 결과 |
|---|---|---|---|
| 1-1 | 정지선 3m 이내에서 마스크가 잡히는가 | **끊기지 않고 계속** 잡힌다 | [ ] |
| 1-2 | 최하단 점이 정지선의 **차 쪽 가장자리**에 붙는가 | 눈으로 확인 | [ ] |
| 1-3 | 차체(앞바퀴·프레임)를 정지선으로 잡는가 | **한 번도 없어야** 한다 | [ ] |
| 1-4 | 횡단보도·차선·그림자·타이어 자국을 잡는가 | 없거나, 잡혀도 `sl` 이 `B1` 보다 큼 | [ ] |
| 1-5 | 정지선이 없는 곳에서 `sl --px` 인가 | 빈 노면에서 검출 0 | [ ] |
| 1-6 | **보정된 화면에서 노면의 직선이 곧은가** | 화면 가장자리에서 안 휜다 | [ ] |

**기록란**

```
정지선이 처음 잡히기 시작하는 거리 = ______ m   ← ★sl_brake1_px 의 상한★
정지선이 차체에 가려 사라지는 거리 = ______ m   ← ★sl_brake2_px 의 하한★
오검출된 것(있으면) : ____________  그때 sl = ______ px
```

**불합격이면 — 순서대로 시도**

| 증상 | 만질 값 | 비고 |
|---|---|---|
| 아예 안 잡힌다 | `sl_conf:=0.15` | 임계를 내려 먼저 격리한다 |
| 얇게/짧게만 잡혀 걸러진다 | `sl_min_width_frac:=0.08` | 기본 0.12 = 화면 폭의 12%(1920px 중 230px) |
| 그래도 안 잡힌다 | `sl_enable:=false` | **접는다.** 모델 재학습 문제지 코드로 풀 수 없다 |
| 엉뚱한 것을 잡는다 | `sl_min_width_frac` ↑ / `sl_conf` ↑ | 1-4 가 불합격이면 여기서 반드시 잡고 간다 |

## 단계 2 — BEV 캘리브 + 두 문턱 정하기 ★차를 세워 놓고 잰다(주행 불필요)★

**이 단계가 이 시험의 무게중심이다.** 기본값 `bev_src_pts` · `bev_bumper_y_px` ·
`sl_brake1_px` · `sl_brake2_px` 는 전부 **근거 없는 값**이다(8항의 25px 과 같은 처지).
순서가 중요하다 — **사다리꼴 → 범퍼행 → 2단 문턱 → 1단 문턱**. 앞의 것이 틀리면
뒤의 것은 잴 의미가 없다.

### 2-A. 사다리꼴(`bev_src_pts`) 맞추기

노면에 **직사각형**을 테이프로 그린다(폭은 차선폭 정도, 길이는 앞범퍼에서 **6~8m**).
화면의 **노란 사다리꼴**이 그 직사각형과 겹치도록 네 점을 옮긴다.

```bash
ros2 launch white1 master.launch.py sl_gate_red_s:=99999.0 \
     bev_src_pts:="[750.0, 560.0, 1170.0, 560.0, 1920.0, 1080.0, 0.0, 1080.0]"
```

- 값은 **좌상, 우상, 우하, 좌하** 순서다(보정된 화면의 픽셀 좌표).
- **밑변**은 화면 아래 끝(1080)에 두는 것이 편하다 — 그러면 밑변이 곧 '카메라가 보는
  가장 가까운 노면'이 된다.
- **윗변을 올릴수록 먼 곳까지** 담는다. 1단 예비제동은 먼 곳을 봐야 하므로
  **BEV 깊이는 최소 6m** 는 되어야 한다(4펄스 1단 정지거리 4.8m + 여유).
- 잘 맞으면 BEV 썸네일에서 **직사각형의 두 변이 평행**하고 정지선이 **가로 막대**로 선다.

| # | 판정 기준 | 합격 | 결과 |
|---|---|---|---|
| 2A-1 | BEV 썸네일에서 직사각형의 두 변이 평행한가 | 눈으로 확인 | [ ] |
| 2A-2 | 정지선이 BEV 에서 **가로 막대**로 서는가 | 기울면 사다리꼴이 비뚤다 | [ ] |
| 2A-3 | BEV 가 담는 깊이(밑변→윗변)가 몇 m 인가 | **≥ 6 m** | [ ] |

```
정한 값 :  bev_src_pts = [____, ____, ____, ____, ____, ____, ____, ____]
BEV 깊이 = ______ m  → 1px = ______ m   (깊이 ÷ 480. bev_px_to_m 에 넣으면 HUD 에 m 가 뜬다)
```

### 2-B. 범퍼행(`bev_bumper_y_px`) 잡기 — ★거리 0 의 기준★

앞범퍼 **바로 앞**(0.1m 이내) 노면에 테이프를 한 줄 붙이고, BEV 썸네일에서 그 줄이
몇 번째 행인지 본다.

- 그 줄이 **BEV 안에 보이면** → 그 행 값을 그대로 `bev_bumper_y_px` 로 준다.
- **안 보이면**(차체가 가려 사다리꼴 밑변이 범퍼보다 앞이다) → 밑변까지의 실제 거리를
  자로 재고 `480 + (그 거리 ÷ 1px당 m)` 을 준다. 즉 **480 보다 큰 값**이 된다.

```
앞범퍼 → 사다리꼴 밑변 = ______ m  →  bev_bumper_y_px = ______
```

### 2-C. 두 문턱(`sl_brake2_px` → `sl_brake1_px`) 정하기

차 **앞범퍼**가 정지선에서 아래 거리가 되도록 차를 대고 HUD 의 `sl` **px** 값을 읽는다.
(한 번 재 두면 다시 잴 일이 없다. 2-A 를 바꾸면 이 표는 전부 무효다.)

| 정지선까지 거리 | 0.5 m | **1.0 m** | 1.5 m | 2.0 m | 3.0 m | **4.0 m** | 5.0 m | 6.0 m |
|---|---|---|---|---|---|---|---|---|
| HUD `sl` [px] | | | | | | | | |

**문턱을 고르는 근거 — `BRAKING.md`**

| | 감속도 | 4펄스(3.54 m/s) 정지거리 | 2펄스(1.77 m/s) |
|---|---|---|---|
| **2단** (확정 정지) | 2.2~3.8 m/s² | 1.6 ~ 2.8 m | 0.4 ~ 0.7 m |
| **1단** (예비제동, 구동 차단) | 1.30 m/s² + 램프 0.55s | **4.8 m** | 2.2 m |

- **`sl_brake2_px`** = 표의 **1.0~1.5m** 칸. 2단은 짧게 세우므로 정지선 앞 여유가
  그만큼만 있으면 된다. ⚠️ **차체 가림 거리(1-1 기록)보다 멀어야** 한다 — 그보다
  가까우면 정지선이 그 문턱에 닿기 전에 화면에서 사라진다(그때는 '놓침' 경로가 받는다).
- **`sl_brake1_px`** = 표의 **4.0~5.0m** 칸(2펄스면 2.0~2.5m). 1단 정지거리에 맞춘다.
  ⚠️ **정지선이 처음 잡히는 거리(1-1 기록)보다 가까워야** 한다 — 안 보이는 거리에
  문턱을 두면 그 구간이 통째로 없는 것과 같다.

| # | 판정 기준 | 합격 | 결과 |
|---|---|---|---|
| 2-1 | `sl` px 가 거리에 대해 **단조 증가**하는가(가까울수록 작음) | 표가 뒤집히지 않는다 | [ ] |
| 2-2 | px 와 m 가 **거의 비례**하는가 | 비례가 깨지면 2-A 가 틀렸다 | [ ] |
| 2-3 | 같은 위치에서 값이 안정적인가 | 흔들림 ±5px 이내 | [ ] |
| 2-4 | `sl_brake1_px` > `sl_brake2_px` 인가 | 뒤집히면 노드가 경고하고 1단을 없앤다 | [ ] |

> **2-2 가 이 단계의 진짜 검산이다.** BEV 로 편 뒤라면 'px ↔ m' 는 직선이어야 한다.
> 휘어 있으면 사다리꼴이 노면 평면에 안 맞은 것이고, 그 상태로 문턱을 잡으면 속도가
> 달라질 때마다 정지 위치가 달라진다.

```
정한 값 :  sl_brake2_px = ______  (____ m 지점)
           sl_brake1_px = ______  (____ m 지점, 접근 ____펄스 기준)
```

## 단계 3 — 판정표 재현 ★차를 세워 놓고, 리니어는 실제로 문다★

사람이 신호등 목업과 정지선 판때기를 들고 움직여 **모든 경로를 밟아 본다.**
차는 굴리지 않는다. `master` 창의 **'신호등 인지' 체크박스를 켜야** 개입한다(D5 는
자율주행 위치여야 리니어가 물린다).

```bash
ros2 launch white1 master.launch.py \
     sl_brake1_px:=<단계 2 값> sl_brake2_px:=<단계 2 값>
```

정지선 판때기를 **천천히 앞으로 가져오면서** BEV 썸네일의 `B1`·`B2` 선을 차례로
넘기는 것이 이 단계의 핵심 동작이다.

| # | 만드는 상황 | 기대 동작 | 기대 로그 | 결과 |
|---|---|---|---|---|
| 3-1 | 빨간불만 보여준다 (정지선 없음) | 0.4초 뒤 **즉시 2단** | `🚦🛑 … [정지선 없음]` | [ ] |
| 3-2 | 빨간불 + 정지선을 **`B1` 밖**(멀리)에 둔다 | **안 문다.** HUD 에 `WAIT` | `🚦⏸ 빨간불 확정 — 정지선 대기 중` | [ ] |
| 3-3 | 정지선을 **`B1` 안**으로 가져온다 | **1단** 체결 | `🚦🟡 … 예비제동 [예비제동] (리니어 0단 → 1단` | [ ] |
| 3-4 | 이어서 **`B2` 안**으로 가져온다 | **2단** 승격 | `🚦🛑 … 정지 [정지선 앞] (리니어 1단 → 2단` | [ ] |
| 3-5 | 3-3 의 1단 상태에서 정지선을 **뒤로 물린다** | **1단 그대로**(안 내려간다) | 아무 로그도 안 난다 | [ ] |
| 3-6 | 3-2 대기 중에 정지선을 **치운다**(가린다) | **0.5초 뒤** 2단 | `🛑 정지선을 놓쳤다 — 이미 선 위다` | [ ] |
| 3-7 | 3-3 의 1단 상태를 **8초 이상** 유지한다 | 8초에 2단 | `🚦 정지선 대기 상한 8.0초 초과` | [ ] |
| 3-8 | 3-2 대기 중 신호등을 **카메라에 바짝** 붙인다 | 즉시 2단 | `🚦 신호등이 코앞이다` | [ ] |
| 3-9 | 3-3 의 1단 상태에서 **빨간불을 치운다** | 1초 뒤 **해제(0단)** | `⚪ 빨간불 1.0초 미감지 — 리니어 해제` | [ ] |

**동시에 확인할 것**

- 3-2 대기 구간에서 `ros2 topic echo /brake_level` 에 **0 아닌 값이 한 번도 안 나온다**
- 3-2 대기 구간에서 `ros2 topic echo /tl_brake_req` 가 **계속 0** 이다
  (이게 0 이 아니면 master·driving 이 대신 물어 버린다)
- `/tl_brake_req` 가 **0 → 1 → 2 로 한 방향으로만** 간다(3-5 가 그것을 직접 본다)
- 1단·2단이 물릴 때 **리니어 소리**가 나고, 해제 시 되돌아온다

> **3-5 가 새 규약(단조 증가)의 시험이다.** 정지선 인지가 흔들려 거리가 왔다 갔다 해도
> 리니어가 1↔2 를 왕복해서는 안 된다. 리니어는 물리적으로 왕복하는 장치이고, 그
> 왕복이 이 시스템에서 제일 나쁜 고장 모드다(2026-08-14 로스백 참고).

> **3-6 이 이 기능에서 제일 미묘한 항목이다.** '놓쳤다'는 적극적 인지가 아니라
> *"`sl_stale_s`(0.5초) 동안 못 봤다"* 를 그렇게 해석하는 것이다. 접근하면 정지선은
> 차체에 가려 **반드시** 사라지므로, 그 소실을 "이미 선 위"로 읽는 것이 안전한 방향이다.
> 대가는 **최대 0.5초의 지연**(2펄스에서 0.9m, 4펄스에서 1.75m)이고, 그 몫은 단계 2의
> `sl_brake2_px` 선택에 이미 들어 있어야 한다.

**판정 기준** (sl_check.py 가 그대로 계산한다)

| # | 항목 | 합격 | 불합격이면 |
|---|---|---|---|
| 4-1 | `sl_wait=True` 구간이 존재하는가 | **≥ 0.3초** | 정지선을 못 봤다 → 단계 1 로 |
| 4-2 | 대기 구간에 `brake_level>0` 이 섞였는가 | **0회** | 다른 발행자가 물었다(driving?) |

| 4-4 | **2단 체결 시각의 `sl_px`** | **`sl_brake2_px` ±10px** | 놓침·상한 경로로 물렸다 |
| 4-5 | **1단 → 2단 사이 시간** | **0.5 ~ 3초** | 너무 짧으면 B1 이 가깝다 / 길면 멀다 |
| 4-6 | 브레이크가 **0 → 1 → 2 한 방향** | 되돌아감 **0회** | 단조 증가가 깨졌다 — 버그다 |
| 4-7 | 정지 사유 로그 | `[예비제동]` → `[정지선 앞]` | `[없음]`=인지실패 / `[놓침]`=B2 가 가깝다 |
| 4-8 | 실제 정지 위치(범퍼→정지선, 자로 잰다) | **0 ~ 1.5 m 앞** | 아래 조정표 |
| 4-9 | 브레이크 채터링(2↔0 왕복) | **0회** | 8항 회귀 — `red_release_hold_s` 확인 |

| 4-12 | 카메라 fps | **≥ 25** | `sl_interval:=2` (왜곡보정이 3~5ms 를 더 쓴다) |

**기록란**

```
접근 펄스 ____ / 대기 시작 시 sl = ______ px
1단 체결 시 sl = ______ px  →  2단 체결 시 sl = ______ px  (사이 ______ 초)
대기 지속 ______ 초 / 대기 중 이동거리 ______ m
실제 정지 위치 : 정지선 ______ m 앞 (앞범퍼 기준)
```

**정지 위치 조정 — 방향을 헷갈리지 말 것**

`sl_px` 는 **가까울수록 작다**(종전 `sl_y` 와 반대다). 따라서

| 증상 | 조치 | 이유 |
|---|---|---|
| 정지선을 **지나쳐** 섰다 | `sl_brake2_px` 를 **올린다** | 더 먼 거리에서 2단을 문다 |
| 정지선보다 **너무 멀리** 섰다 | `sl_brake2_px` 를 **낮춘다** | 더 가까이 붙어서 문다 |
| 감속이 **급하다**(2단이 다 감당) | `sl_brake1_px` 를 **올린다** | 1단을 더 일찍 물어 미리 줄인다 |
| 정지선 **한참 앞에서 멈춰** 버린다 | `sl_brake1_px` 를 **낮춘다** | 1단이 너무 일러 다 죽였다(구동이 끊겨 재출발 못 한다) |
| `대기 상한 8.0초 초과` 가 뜬다 | 위와 같음 + `sl_brake2_px` ↑ | 1단으로 멈춰 B2 에 못 닿았다 |
| 지나쳤는데 로그가 `[정지선 놓침]` | `sl_stale_s:=0.3` 도 함께 | 소실 판정이 늦어 0.5초를 더 갔다 |

한 번에 한 값만 바꾸고 4단계를 다시 돈다. 2펄스에서 4-1~4-12 를 전부 통과한 뒤에만
4펄스로 올린다(**두 문턱도 단계 2 표의 4~5m·1~1.5m 칸으로 함께 바꾼다**).

## 부록 B — CSV 열 읽는 법

`record.py` 가 남기는 정지선 관련 열은 셋이다.

| 열 | 뜻 |
|---|---|
| `sl_px` | **★판정값★** BEV 에서 정지선 → 앞범퍼 픽셀 거리. **−1 = 미검출 / 0 = 도달·지나침** |
| `sl_y` | 정지선 최하단 y ÷ 프레임 높이(0~1). **판정에는 안 쓴다** — 영상 대조용 |
| `sl_wait` | RED 확정인데 정지선이 멀어 **아직 아무 단계도 안 건** 구간 |

신호등 3열과 나란히 놓으면 판정 경로가 그대로 드러난다.

| `tl_state` | `sl_px` | `sl_wait` | `brake_level` | 해석 |
|---|---|---|---|---|
| RED | 380 | True | 0 | 빨간불 확정, 정지선이 아직 멀다 — **의도한 동작** |
| RED | 210 | False | **1** | **1단 예비제동 중** — B1(240) 을 막 넘었다 |
| RED | 55 | False | 2 | 정지선 앞에서 2단 — **정상** |
| RED | −1 | False | 2 | 정지선을 못 보고 그 자리에서 섰다 — 종전 동작 |
| RED | −1 | False | 1→2 | 1단으로 가다 정지선을 놓쳐 2단 — B2 가 가깝다 |
| RED_FAR | 500 | False | 0 | 멀다고 보고 안 섰다 — 정상 |

**`brake_level` 이 1 에서 2 로 가는 행의 `sl_px`** 가 곧 실제 정지 지점의 근거다.
그 값이 `sl_brake2_px` 와 크게 다르면 '정지선 앞'이 아니라 상한·놓침 경로로 물린 것이다.
